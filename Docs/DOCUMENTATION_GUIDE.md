# Ведение документации проекта

> **Дата:** 7 апреля 2026  
> **Цель:** правила создания, обновления и организации документации

---

## 1. Структура документации

Все документация хранится в папке `Docs/`:

| Файл | Для кого | Содержание |
|------|----------|-----------|
| `README.md` | Игроки | Как запустить, управление, геймплей, описание игры |
| `README_DEV.md` | Разработчики | Техническая архитектура, иерархии сцен, сигналы, слои коллизий |
| `CODEBASE_STANDARDS.md` | Разработчики | Стандарты кода, принципы, типизация, именование, паттерны |
| `GAME_REQUIREMENTS.md` | Продукт/Разработчики | Полный список требований к игре |
| `TASKS.md` | Разработчики | Чек-лист задач: что сделано, что предстоит |

### Удалить (архив)
Следующие файлы дублируют новую документацию и не нужны при новой разработке:
- `GENERAL_GAME_REQUIREMENTS.md` → перенесено в `GAME_REQUIREMENTS.md`
- `MAZE_GAME_SPECIFIC_REQUIREMENTS.md` → перенесено в `GAME_REQUIREMENTS.md`
- `GAME_IMPROVEMENTS.md` → перенесено в `TASKS.md`
- `MAZE_IMPROVEMENTS.md` → перенесено в `TASKS.md`
- `MODERN_GAME_REQUIREMENTS.md` → перенесено в `GAME_REQUIREMENTS.md`
- `CODEBASE_STANDARDS.md` (корневой) → перенесено в `Docs/CODEBASE_STANDARDS.md`

---

## 2. Когда обновлять документацию

### При изменении кода

| Изменение | Что обновить |
|-----------|-------------|
| Новая механика | `GAME_REQUIREMENTS.md` + `README.md` (если видно игроку) |
| Новый сигнал | `README_DEV.md` (таблица сигналов) |
| Новый параметр в Settings | `GAME_REQUIREMENTS.md` (секция настроек) |
| Новый слой коллизий | `README_DEV.md` + `CODEBASE_STANDARDS.md` |
| Изменение структуры файлов | `CODEBASE_STANDARDS.md` + `README_DEV.md` |
| Новая сцена/скрипт | `README_DEV.md` (иерархия сцен) |
| Изменение архитектуры | `README_DEV.md` + `CODEBASE_STANDARDS.md` |
| Выполненная задача | `TASKS.md` (отметить ✅) |
| Новая задача | `TASKS.md` (добавить в список) |

### При завершении фазы
После завершения каждой фазы разработки (Phase 1, 2, 3) — полная проверка всех документов на актуальность.

## 3. Правила оформления

### 3.1 Формат
- Все файлы в **Markdown** (`.md`)
- Код в блоках ```gdscript
- Таблицы для структурированных данных
- Чек-листы через `- [ ]` / `- [x]`

### 3.2 Язык
- Документация на **русском языке** (команда)
- Технические термины на английском (signal, autoload, spawn и т.д.)
- Код и имена переменных — как в проекте (английский)

### 3.3 Заголовок каждого файла
```markdown
# Название документа

> **Проект:** Maze: Coins and Exit  
> **Дата:** 7 апреля 2026  
> **Цель:** краткое назначение документа
```

### 3.4 Нумерация разделов
Иерархическая нумерация:
```
1. Раздел
1.1 Подраздел
1.1.1 Пункт
```

## 8. TASKS.md (для разработчиков)

### Содержит
- Полный чек-лист всех задач
- Что уже сделано ✅
- Что предстоит ⏳
- Разделение по фазам
- Приоритеты

### Обновлять когда
- Задача выполнена → отметить `[x]`
- Новая задача → добавить в соответствующую секцию
- Изменился приоритет → переместить в другую секцию

---

## 9. Версионирование документации

- В заголовке каждого файла указывать **дату последнего обновления**
- При значительных изменениях (>30% документа) — создавать новую версию файла с суффиксом `_v2.md`, `_v3.md`
- Старые версии перемещать в `Docs/Archive/`

---

## 10. Проверка актуальности

Перед каждым релизом (или значительным коммитом):
1. Прочитать все документы целиком
2. Сравнить с текущим состоянием кода
3. Исправить все несоответствия
4. Обновить даты в заголовках

**Частота:** минимум раз в 2 недели при активной разработке.
